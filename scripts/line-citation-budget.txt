# Per-file budget for `path.rs:LINE` citations in tracked Markdown.
#
# A line number into a churning file is a citation the next edit to that file
# silently breaks. Measured 2026-09-19: four citations into
# `crates/tf_tree/src/{open,tree}.rs` already pointed at a blank or bare-`///`
# line on `main`, and a seven-line rustdoc edit in one PR moved twenty-two more.
# Twenty-three of those sites sit in `implemented` records, which this project
# freezes, so they cannot be repaired in place.
#
# The existing ones are grandfathered and the count may only fall. Cite a
# **symbol** instead — `reclamation_verdict` in `crates/tf_tree/src/open.rs` —
# which survives every edit that does not rename it.
#
# Fenced blocks are excluded (a `path:line` there is compiler output); code
# spans are not, because that is where these citations are written.
#
# `just lint` refuses any increase **and any decrease left unrecorded**: each
# row is an equality with what the scanner matches in its file, so shedding a
# citation means lowering the number here in the same commit.
#
# **The scanner matches only the full-path form**, `crates/.../tree.rs:2182`
# and not a bare `tree.rs:2182`, and the bare form is the one `CLAUDE.md`'s
# rule names. Measured 2026-09-19: 154 counted, 404 with the prefix optional.
# These numbers are therefore a floor on the rot, not a census of it.
#
# A row sitting above its file is headroom for a citation nobody had to
# justify — and, until 2026-09-19, the way to raise a budget without anyone
# noticing, because a drop was only a printed note.
#
# **One row was ADDED after the fact, on 2026-09-19, and that is not a licence
# to add more.** `docs/PHASE5.md` had no row because the scanner reported zero
# for it while the file carried three, one of which the same commit converted to
# a symbol — so the row is 2, which is what the file carries *now* rather than
# what it always did. Stating that plainly because a row added for any reason
# other than "the scanner could not see these" is a budget being raised.
# The cause: the first fence-stripper was `re.sub(r"```.*?```", ...)`, which
# counted a triple backtick written inside an inline code span, and an odd
# marker count inverts the pairing for the rest of a file — prose blanked, code
# blocks scanned. The stripper is line-anchored now (`strip_fenced_blocks`).
