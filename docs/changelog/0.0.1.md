## [0.0.1] — 2026-08-17 (crates.io only)

First publish; no wheel (PyPI refused `tf_tree`; the distribution is `transform_tree` from 0.0.2).

### Added

- Engine (`PHASE1.md`): fixed-capacity `#[repr(C)]` arena, seqlock rings, compiled `Plan` lookups, `tf_tree_math`, domain-typed nanosecond stamps, `Copy` errors, builder-time edge declaration (`0004`).
- Shared memory, Linux, `shm` feature (`PHASE2.md`): `tf_tree::open()` rendezvous, participant registry, OFD-lease claims, reaping, fork poisoning.
- Python bindings (`PHASE3.md`): `tf_tree.open()`, NumPy batch lookup, `at_into`, free-threaded `cp314t`.
- C ABI 0.5, `tf_tree.hpp`, `at_with_derivatives`, one-way ROS 2 `/tf` ingest bridge (`PHASE4.md`); only `at_with_derivatives` is published.
- `FORMAT_VERSION = 3`, frozen `.tft`, MCAP ingestion, `tf_tree.open_file()`, `counters` feature, `TFT001`–`TFT019` via `tf_tree doctor`, `tf_tree top` (`PHASE5.md`).

### Not published

- Published: `tf_tree`, `tf_tree_core`, `tf_tree_math`, `tf_tree_arena`, `tf_tree_ipc`. Everything else, including `tf_tree_cli` and `tf_tree_c`, is build-from-source.

### Absent

- `tf2` shim and egress (Phase 7), cross-host (Phase 8), B-splines (Phase 6), visualization (`PHASE5.md` §8), ROS 1, rosbag2 `.db3`, `tf_tree serve` (`0019`).

### Partial

- No trigger for ownership migration (`PHASE2.md` §3.5): after the owner dies no new process can join.
- `TFT002`, `TFT003`, `TFT004` cannot detect anything; `at_into` accepts only `numpy.ndarray`; `freeze_from_arrays` is not implemented; Phase 4's operational exit criterion is open.
