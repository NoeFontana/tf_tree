## [0.0.3] — 2026-08-19 (first with a source distribution)

### Known issues

- A process's lock byte and its arena participant record can carry different indices (#201); pinned by `defect_201_a_forced_creators_record_reads_dead_while_it_is_publishing`, `0028` question 3. `Tree::reparent` decides topology-lock liveness from `/proc` even on a tree holding an OFD probe (#213); see `PHASE2.md` §0.0.

### Fixed

- `0.0.2` had no sdist: `[tool.maturin] include` now carries the licence files and the `sdist` job gates `publish` (#179). `Tree::lookup`'s per-thread plan cache could serve one tree's plan to another (#196); the key now carries an arena identity, also fixing `tf_tree_py`.
- The liveness predicate could report a running process dead: unmounted `/proc` and a stored start time of `0` now read as unknown, and `process_start_time` returns an `Option` (#194).
- `RUNBOOK.md` named a nonexistent `--force-new` flag and the wrong cause for `ArenaHeldButUnreachable`; it now names `CreatePolicy::Always` and says to stop every participant (#189). `PHASE2.md` §0.0 records that the identity triple is still correctness-critical (#205); `tests/frozen.rs`'s litter check no longer matches other processes' files.

### Added

- `tf_tree_math::slerp` is public; `tf_tree` re-exports `slerp` and the `dualquat` module.
- `just artifact-versions` checks every Markdown table's rows against its header; `just shm-check` runs `--lib`; `just py-compile` falls back to the `PATH` interpreter and runs `cargo fmt --check` for `tf_tree_py`; `just gate4-python` re-derives PHASE5 §12 gate 4's Python arm (`frozen_workers --python`); it reports and exits 0.
- `tf_tree doctor`'s `TFT014` reports leaked participant slots (#190, `0028` step 6); it now skips on `doctor --from-file` where it reported `pass`.
