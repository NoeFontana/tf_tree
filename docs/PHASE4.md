### §7 gate criterion 1 — state

Measured by `just abi-cost` at `[profile.embedder]` (`lto = false`), interleaved, as four quotients rather than the single ratio §7 once named ([`0023`](./decisions/0023-the-gate-that-could-not-gate.md)). The single quotient is withdrawn: its denominator moved 43% on an unrelated edit to the same binary, so neither the 1.020× PASS nor the 1.34–1.46× FAIL it once recorded is a statement about the ABI. The workspace `release` profile (`lto = "thin"`) inlines `tft_plan_at` into a Rust caller and erases the boundary; a reading without its profile is the error to avoid.

| row | what it is | measured | allowance |
|---|---|---|---|
| **R1** | `tft_plan_at` over native in the shape the C signature forces | 1.025–1.038× | < 1.10 (provisional) |
| **R2** | the panic guard (`catch_unwind`) | 0.999–1.006× | < 1.05 |
| **R3** | a guard per lookup, over one hoisted out of the loop | 1.059–1.075× | not yet set on §11.1's fixture; reported, not gated |
| **C** | control: R1's structural twin | 0.992–1.002× | 1 ± 0.02 |

- `just abi-cost` exits non-zero on a failing gated row and runs in no workflow; readings are registered in [`EVIDENCE.md`](./benchmarks/EVIDENCE.md)'s `abi_cost` row, enforced by `just evidence-audit`.
- The ABI's own cost is ~+6 ns. The per-call `Guard` costs ~45 ns on an attached shared arena and ~16 ns on the three-edge heap tree; the difference is the fixture (a cold bracket-search cursor over a larger stamp array), not the backing.
- `catch_unwind` costs +0.6 ns on a real, non-inlinable call. The publish path costs 2.5× native (22 ns against 8.8 ns) because the C ABI checks at run time what Rust's types settle at compile time.
- R3's remedy is `tft_plan_at_many` (one guard per batch), not a guard handle ([`0022`](./decisions/0022-the-per-call-guard-and-the-unwatched-gate.md)).

### §7 gate criterion 2 — closed

`plan.at<Eigen::Isometry3d>` against `tft_plan_at` passes in both error modes. The `-fno-exceptions` shortfall was NRVO: `Plan::at` had two `return` statements, so the compiler abandoned NRVO and copied the 456-byte `expected` on the success path. The fix is `TF_TREE_FAIL_INTO` (assign the `Error` into `out`, one `return` in both modes).

**The durable statement of the gate is the structural test; the benchmark only reports.** `check_at_writes_into_the_returned_object` links with `-Wl,--wrap=tft_plan_at` and asserts the pointer the ABI receives is the address of the returned object; restoring `TF_TREE_FAIL(s)` fails both `--wrap` no-exceptions rows of `just cpp-check`. `check_fail_into_leaves_the_function` pins that the macro leaves the function in both modes. `--wrap` is GNU-ld/lld only, so it stays out of the eight-row portability matrix. A single `just cpp-bench` ratio is evidence of nothing on its own (~4% run-to-run spread).

### Findings the design must keep

- **Layout read direction.** A publisher needs four layouts as *inputs*: matrix→quaternion by Shepperd's four-branch method, plus a determinant check (`det R = −1` is a reflection, `det R = s³` a scaled `Affine3d`; both otherwise convert silently). `AFFINE12_ROW_F32` is write-only.
- **Id spaces.** Both `EdgeId` and `FrameId` report `1 ..= count` across the C ABI. `instance_uuid` of a private arena is zero, so `tft_tree_instance_uuid` returns `TFT_ERR_NO_DATA` rather than making two unrelated trees compare equal.
- **Bridge ordering (`tf_tree_bridge`).** Names normalized before anything keys on them; static-value check before authority (else §5.7 is inert under `FirstWriterWins`); authority before the clock (else the victim is blamed); a static's stamp never touches the clock. A backward stamp is not automatically a reset: interleaved publishers regress by milliseconds, so the reset threshold is 100 ms by default.
- **`recreate` stops the bridge exactly like `halt`.** The ABI cannot recreate the arena, and unlatched, the pipeline has already accepted the rewound stamp.
- **`TFT_BRIDGE_REJECTED` is unreachable from a heap-arena bridge**, by proof: each edge's clock guard dominates that edge's ring and only `Recreate`, which latches first, rewinds it. The arm stays because breaking that invariant would present as "applied, but no data".
- **The outcome POD is written twice per offer on purpose**: the blank write must precede handle validation so `a_bad_handle_still_leaves_a_printable_outcome` holds.
- **Empty topology.** `tft_bridge_create("")` returns `TFT_OK` at the engine (a tree with no edges is legal); the refusal lives in `tft_bridge_create` and `BridgeNode`'s both-or-neither parameter check.
- **Attribution is §5.4's input.** Measured with the GID cache disabled, both publishers resolved to `<unknown publisher>` and 996 samples from two nodes were applied to one edge. `MessageInfo::publisher_gid` equals the graph endpoint's `endpoint_gid()` on `rmw_fastrtps_cpp` (`RMW_GID_STORAGE_SIZE == 16`).
- **Attribution refresh is on the ingest thread, before offering**, triggered by an unseen GID and capped at 20 walks per unmatched GID. A periodic refresh is wrong: under `FirstWriterWins` the first sample fixes the owner's name.
- **Static-archive build.** `ros/build.sh` links the static target (a rustc cdylib has no `DT_SONAME`), makes one `nm` symbol check per default-off feature (`bridge`, `shm`), and deletes `*/test_results` before `colcon test`. `TFT_HAVE_SHM` is probed per target by `crates/tf_tree_c/CMakeLists.txt`.
- **`is_trivially_copyable` is the wrong gate for a raw layout write**: `Eigen::Transform` declares a copy constructor. The wrapper uses the `tf_tree::raw_writable<T>` customisation point plus a run-time premise check.
- **CMake packages are tested by a separate consumer** (`just cmake-check`).
- Measured: `Sophus::SE3d` is 64 bytes against a 56-byte payload (§4.3's stride hazard is real); Eigen strided and packed writes cost the same.
- `examples/bridge_cost.rs` (20 edges) reports the per-offer half of the bridge row; it is **not** gate criterion 3. `tests/steady_state_alloc.rs` in `tf_tree_bridge` budgets 2 allocations per accepted or undeclared offer and 0 per refused one. `just bridge-footprint` measures instructions per offer (flat in edge count after interning: ~900 `Ir`).

### What this environment cannot gate

- **ROS 2 is available in `docker/tf2`** (`ros:lyrical-ros-base`, `rmw_fastrtps_cpp`, `rosbag2_cpp` with MCAP). A mock DDS is not needed; §5.4–§5.7 are pure functions and host-testable.
- **One RMW.** §5.3's degrade-gracefully path (all-zero GIDs skipped, unmatched GIDs retried then abandoned) is implemented and untested.
- **No clang in the ROS image**; the C ABI and wrapper still get both compilers via `just c-header-check` and `just cpp-check`.
- **§6.3's remaining rows** (bag replay at 10× real time; byte-identical arenas across the three forms) need a bag through `rosbag2_cpp` and a byte-for-byte arena comparison.
- **§5.9's CPU affinity and `SCHED_FIFO`** are not implemented.
- **`message_lost_callback` and `incompatible_qos_callback`** fire in no test; `BridgeOptions::queue_depth` is asserted (negotiated depth), its effect is not.
- **No robot, no two-week window.** §1's criteria gate Phase 7 and stay open; nothing in §5 satisfies them.
- **The benchmark host is not a fair comparison machine** (4 physical cores with SMT, `perf_event_paranoid=4`; Phase 1's read-scaling gate measures 5.35–5.62× against ≥ 6×). §7 gate criterion 3 prints `UNAVAILABLE` with a reason.

## 1. What Phase 4 must prove

Feature completion is not the gate. The gate is:

1. **A real node, on real hardware, for ≥ 2 weeks continuous**, consuming transforms from `tf_tree` via the bridge, with no correctness incident.
2. **A written log of every surprise** — API friction, missing operations, confusing errors, deployment papercuts. This log is the design input for Phase 7.

   > [`PHASE7.md`](./PHASE7.md) §4 is a table of the semantic judgements the shim must make. **Every log entry is filed against a J-row or opens a new one**; that is the only Phase 7 work authorized before its §0.0 gates are met. A J-row answered from `PHASE7.md` instead of from this log is the guess D21 exists to prevent. Entries about *our* design rather than `tf2`'s behaviour get their own decision record ([`0017`](./decisions/0017-owned-handles-and-the-lifetime-rule.md), [`0018`](./decisions/0018-blocking-waits-belong-in-the-shim.md)).
3. **At least one pre-existing bug found in the host system** by the bridge's multi-publisher detection (§5.4). This is a falsifiable prediction: real ROS systems routinely have two nodes publishing one edge, and `tf2` averages them silently. If two weeks finds nothing, either the detection is broken or the host stack is unusually clean — determine which.

Do not proceed to Phase 5 having only met criterion 1.

## 2. `sample_with_derivatives` — pulled forward

### 2.1 Why now

It is the clearest signal that `tf_tree` is a different primitive rather than a faster `tf2`, greenfield users pay no migration cost, and it adds no transcendental call under ScLerp.

### 2.2 API

```rust
pub struct Twist { pub omega: Vec3, pub v: Vec3 }   // body frame (right), rad/s and m/s

pub struct Sample {
    pub pose:  Iso3,
    pub twist: Twist,
    pub accel: Option<Twist>,   // None for ScLerp/LerpSlerp; Some(_) for splines (Phase 6)
}

impl Plan {
    pub fn at_with_derivatives(&self, g: &Guard, t: Stamp) -> Result<Sample, LookupError>;
}
```

**Convention — NORMATIVE:** twists are **body-frame (right) twists**, `V^b = (T⁻¹ Ṫ)^∨`, matching the right-perturbation convention of Phase 1 §3.1. `Twist::to_spatial(&self, t: &Iso3)` = `Ad(T) V^b`. The type name and docstring carry the convention.

### 2.3 ScLerp gives an exact, constant body twist

For `T(s) = a · exp(s · ξ^)` with `ξ = log(a⁻¹b)` and `s = (t − t₀)/Δt`:

```
V^b(t) = ξ / Δt        — constant across the whole segment
```

Verified against central differences: max relative error 2.4 × 10⁻⁷, constant across `s ∈ {0, 0.17, 0.5, 0.83, 1}`.

> **Amendment — `ξ` is not computed by `ScLerp::eval`, which works in unit-dual-quaternion screw form (`crates/tf_tree_math/src/interp.rs:61`), so the first derivative is not "one scalar multiply".** `ξ` is recoverable from the intermediates without an additional transcendental: on the large-arc branch `phi` and `sh` are already materialised; on the small-angle branch it costs two `sqrt`s. `screw_pow` is `pub`, so the derivative path should gain a variant returning the screw intermediates alongside the pose rather than recompute them.

Composition along a plan (verified to ~5 × 10⁻¹¹; add both as proptests):

```
T_ac = T_ab · T_bc   ⇒   V_ac^c = Ad(T_bc⁻¹) · V_ab^b + V_bc^c
S = T⁻¹              ⇒   V_S^b   = −Ad(T) · V_T^b
```

> **Amendment — "6×6 adjoint" is the identity, not a representation.** For `T = (q, t)`, in existing primitives (two `Quat::rotate` and one `Vec3::cross` per step; nothing in `crates/tf_tree_math/src/lib.rs:15` builds a 6×6):
>
> ```text
> Ad(T⁻¹)·[ω; v] = [ q*·ω ;  q*·(v − t × ω) ]
> Ad(T) ·[ω; v] = [ q·ω  ;  t × (q·ω) + q·v ]
> ```

### 2.4 LerpSlerp and ScLerp differ in the linear part

They produce the same angular velocity. Body-frame linear velocity across `s = 0.05 → 0.95` on one random segment:

```
LerpSlerp   v = [ 34.31, -0.75, 18.49] → [ 15.73, -35.43, -4.08]   spread 34.7
ScLerp      v = [ 25.997, -27.519, 20.879] → identical              spread 1.5e-10
```

LerpSlerp's `|v|` is constant to 4 × 10⁻¹¹ while the vector swings by 34.7, so **a magnitude check will not catch this**. Its world-frame velocity is constant, so the body-frame velocity rotates through the segment: a spurious lateral acceleration that is an artifact of the interpolant, and a concrete reason ScLerp is the default.

**NORMATIVE:** `at_with_derivatives` returns `Err(DerivativesUnavailable { edge, interp })` for `LerpSlerp` edges rather than a misleading value.

## 3. The C ABI

### 3.1 Two tiers — NORMATIVE

The first ABI freeze in the project; the surface is permanent, so keep it small.

| Header | Contents | Guarantee |
|---|---|---|
| `tf_tree.h` | open/close, plan, at, at_many, publisher, declare, errors, version | **semver, frozen at 1.0** |
| `tf_tree_unstable.h` | everything else — introspection, diagnostic counters, adaptive, derivatives | none; requires `#define TFT_ENABLE_UNSTABLE` |

**Do not mirror the Rust API into C.** Anything a C++ user does not need in the hot path belongs in the unstable header.

### 3.2 Handles and ownership

```c
typedef struct tft_tree      tft_tree;       // Send + Sync   -> shareable across threads
typedef struct tft_plan      tft_plan;       // Send + Sync   -> shareable, immutable
typedef struct tft_publisher tft_publisher;  // Send + !Sync  -> ONE THREAD AT A TIME
```

Every `tft_*_create`/`_open` pairs with exactly one `tft_*_free`. Freeing NULL is a no-op. Double-free is undefined and detected in debug builds by a magic word in the handle header.

**`tft_publisher` thread affinity — NORMATIVE.** Record the creating thread id in the handle and, in debug builds, `abort()` with a clear message on use from another thread. `tft_bridge` has the same affinity; freeing it from the wrong thread is refused and leaks the handle (`TFT_ERR_WRONG_THREAD` in release, `SIGABRT` naming `tft_bridge` in debug).

### 3.3 Error model

Status code plus a thread-local structured detail.

```c
typedef int32_t tft_status;   /* 0 = ok; negative = error */

typedef struct {
    uint32_t struct_size;          /* = sizeof(tft_error) at compile time */
    tft_status code;
    uint32_t edge;                 /* TFT_INVALID_ID when N/A */
    uint32_t frame_a, frame_b;
    int64_t  requested, oldest, newest;
    uint64_t plan_generation, current_generation;
    char     message[256];         /* NUL-terminated, names resolved */
} tft_error;

const tft_error* tft_last_error(void);   /* thread-local; valid until the next tf_tree call
                                            on THIS thread; never NULL */
```

Message formatting happens only on the error path. Document the thread-local lifetime in the header itself: it is the most common C-API misuse.

### 3.4 Panic safety — NORMATIVE

A panic escaping an `extern "C"` function aborts the process. **Every `extern "C"` entry point wraps its body in `std::panic::catch_unwind`**, converting a panic into `TFT_ERR_INTERNAL` with the payload copied into `message`. A benchmark row proves the happy-path cost (§7).

### 3.5 Layouts — and the quaternion order trap

```c
typedef enum {
    TFT_LAYOUT_QVEC7_WXYZ = 0,   /* [qw qx qy qz tx ty tz] f64 — canonical, matches the arena */
    TFT_LAYOUT_QVEC7_XYZW = 1,   /* [qx qy qz qw tx ty tz] f64 — Eigen/Sophus coefficient order */
    TFT_LAYOUT_MAT4_COL   = 2,   /* 4x4 f64 column-major — Eigen                               */
    TFT_LAYOUT_MAT4_ROW   = 3,   /* 4x4 f64 row-major — C, NumPy                               */
    TFT_LAYOUT_AFFINE12_ROW_F32 = 4,  /* 3x4 f32 row-major — GPU                               */
} tft_layout;
```

Two traps, both producing plausible wrong answers rather than crashes:

**Quaternion component order.** Canonical is `w`-first; `Eigen::Quaterniond`'s internal storage is `(x, y, z, w)`. A `memcpy` from `QVEC7_WXYZ` into an `Eigen::Quaterniond` or `Sophus::SE3d` is silently wrong. `QVEC7_XYZW` exists to make the correct thing the easy thing.

**Matrix major order.** Row- and column-major differ by a transpose, which for a rotation is its inverse. Never infer major order from context; the enum is explicit and there is no default.

**NORMATIVE test:** for every layout, round-trip a known transform through the C ABI and assert against a hand-computed expected byte pattern, not against another tf_tree call.

### 3.6 ABI versioning

```c
uint32_t tft_abi_version_major(void);
uint32_t tft_abi_version_minor(void);
```

**Major must match exactly**; the runtime minor may be ≥ the compiled-against minor. Every struct passed by pointer begins with `uint32_t struct_size`, so fields can be appended without a major bump; the callee validates `struct_size` and rejects unknown sizes.

**Appending a `tft_layout` enumerator is a minor bump**: an older caller never names it, and `tft_plan_at` rejects an unknown enumerator (`bad_enum("layout")`). This is the path [`API.md`](./API.md) §3.3 uses to carry `Layout::QuatTwist` into C and Python in Phase 5.

The C++ header checks the version in a static initializer and throws / aborts on mismatch with both versions named.

### 3.7 The hot path

```c
tft_status tft_plan_at(const tft_plan*, int64_t stamp, tft_layout, void* out);
tft_status tft_plan_at_many(const tft_plan*, const int64_t* stamps, size_t n,
                            tft_layout, void* out, size_t out_stride_bytes);
```

`out_stride_bytes` writes directly into an array of user structs whose element size exceeds the payload (§4.3). Zero means tightly packed. No allocation, no locking. Gate: §7 criterion 1.

## 4. The C++ wrapper

### 4.1 Shape

Header-only, C++17, `namespace tf_tree`. RAII handles with deleted copy and defaulted move. Two error modes selected at include time:

- Default: throws `tf_tree::Error` carrying the full `tft_error` as accessors.
- `#define TF_TREE_NO_EXCEPTIONS`: every call returns `tf_tree::expected<T, Error>` (`std::expected` when C++23 is available).

No logic: every function is a thin inline over the C ABI.

### 4.2 Eigen interop

```cpp
Eigen::Isometry3d T = plan.at<Eigen::Isometry3d>(stamp);

std::vector<Eigen::Isometry3d> out(n);
plan.at_many(stamps, out);            // writes straight into out.data()
```

`Eigen::Isometry3d` is a 128-byte column-major `Matrix4d` (alignment 16, or 32 under AVX), so **an array of them is tightly packed and `TFT_LAYOUT_MAT4_COL` writes into it with no copy and no stride.** Assert it:

```cpp
static_assert(sizeof(Eigen::Isometry3d) == 128, "unexpected Eigen Transform layout");
```

C++17's over-aligned `new` makes `std::vector<Eigen::Isometry3d>` correct without `Eigen::aligned_allocator`; `static_assert(__cplusplus >= 201703L)` on the convenience overload.

### 4.3 Sophus interop and the alignment hazard

`Sophus::SE3d` is an `Eigen::Quaterniond` (32 B) plus a `Vector3d` (24 B): a 56-byte payload whose `sizeof` rounds up, commonly to 64. **An array of `SE3d` is usually not tightly packed**, and a `memcpy` of `n × 56` bytes corrupts every element after the first. `out_stride_bytes` is for this:

```cpp
plan.at_many(stamps, TFT_LAYOUT_QVEC7_XYZW, out.data(), sizeof(Sophus::SE3d));
```

`sizeof` depends on the user's Eigen flags, so it is read at compile time from their build, never assumed; the wrapper checks the quaternion precedes the translation with no interior padding before enabling the direct path, else falls back to an element-wise loop.

### 4.4 Packaging

- `find_package(tf_tree CONFIG)` exporting `tf_tree::tf_tree` (shared) and `tf_tree::tf_tree_static`, with `INTERFACE_COMPILE_FEATURES cxx_std_17`.
- Source builds via **`corrosion`**, so `colcon build` works without hand-managed cargo.
- **Requiring a Rust toolchain is real adoption friction.** Ship prebuilt static libraries for `x86_64` and `aarch64` `linux-gnu`, and prefer a prebuilt when the target matches. A ROS binary package (bloom/rosdep) is Phase 7.

## 5. The ROS 2 ingest bridge

### 5.1 Ingress only — NORMATIVE

The bridge subscribes `/tf` and `/tf_static` and writes into the arena. It does **not** publish.

### 5.2 QoS — get this wrong and you silently receive nothing

**NORMATIVE**, matching `tf2_ros::TransformListener`:

| Topic | QoS |
|---|---|
| `/tf` | `KeepLast(100)`, **reliable**, **volatile** |
| `/tf_static` | `KeepLast(100)`, **reliable**, **transient_local** |

A `volatile` subscription to `/tf_static` receives nothing from publishers that started earlier and never publish again: the most common ROS 2 tf integration bug, with no error anywhere. Log the negotiated QoS at startup and warn on any incompatibility event.

> **Clarification — "negotiated" is load-bearing.** The startup line reports `Subscription::get_actual_qos()` read back at construction, not the request. `incompatible_qos_callback` is installed on both subscriptions. `reliable` on `/tf` has no delivery consequence a test can wait for (`best_effort` is compatible with a reliable publisher), so `test_qos.cpp` asserts both fields and the depth directly against `get_actual_qos()`.

### 5.3 Publisher attribution — the bridge is a bug detector

`TFMessage` carries no publisher identity, but the middleware does: `rmw_message_info_t::publisher_gid` matches `TopicEndpointInfo::endpoint_gid()` from `Node::get_publishers_info_by_topic("/tf")`, which also gives `node_name()` and `node_namespace()`. Cache the match, refreshed before offering a message whose GID is unseen (§5.8's threading rule forbids a graph-event handler).

**Degrade gracefully:** GID reporting varies across RMW implementations. On failure keep running with the publisher unattributed.

> **Amendment — the identity is the GID; the name is presentation.** A node name is not stable (`rmw_fastrtps` reports `_NODE_NAME_UNKNOWN_` until node information arrives), so comparing publishers by name made `FirstWriterWins` treat one publisher as an intruder permanently (10 070 transforms received, 187 applied, 100% of lookups failing).
>
> - `Publisher::Gid` carries the rendered GID as identity and the node name as `Option<String>`; `PartialEq`, `Ord` and `Hash` read the identity alone and are hand-written so a new field cannot rejoin the key.
> - `tft_bridge_attribute` updates a name, never an identity.
> - A GID with no name is a distinct publisher and prints its GID.
> - `Publisher::Unattributed` (no GID at all) stays a unit variant: less attribution means less detection, never more stopping.
> - Offline ingest identifies a publisher by the recording's topic (`Publisher::Topic`).

> **Amendment ([`0012`](./decisions/0012-the-authoritative-clock-jump-signal-and-the-degradation-ladder.md)) — "never a correctness dependency" is a constraint on the decision pipeline.** Unit-variant publishers all compare equal on an RMW without GIDs; `0011`'s corroboration floor, derived from a distinct-publisher count, was then permanently 1 and every single-edge stamp regression halted the bridge.
>
> - **No decision that can stop, restart or refuse the bridge may be a function of publisher identity or of the number of distinct publishers.** Identity may change what is reported, never what is done.
> - **A detector degrades in sensitivity, never toward action.**
> - §5.5's ladder satisfies both by construction: a single witness never halts, at any magnitude.

### 5.4 Authority policy — NORMATIVE

ROS permits any number of publishers per edge; `tf_tree` permits exactly one (D7).

| Policy | Behaviour |
|---|---|
| `FirstWriterWins` (**default**) | The first attributed publisher of an edge owns it. Later publishers' samples are dropped and counted, with a diagnostic naming **both** nodes and the edge. |
| `LastWriterWins` | Reclaim on each new publisher. Documented as chaotic, never the default. |
| `Strict` | Refuse to start if a conflict is detected within a startup window. For CI. |

> **Amendment ([`0011`](./decisions/0011-the-bridge-clock-guard-and-the-static-conflict-disposition.md)) — `Strict` halts once at the close of the startup window, not on the message that conflicts.** CI wants every misconfiguration in one run, and `/tf_static` is `transient_local`, so when a conflict is observed is a discovery artefact.
>
> - The window is open from construction and closes at the first of: an explicit `close_startup_window()` (primary; the `rclcpp` node drives it from a one-shot **steady** timer, `startup_window_sec` default 5.0, never `node_->get_clock()`); or a backstop of 4096 transforms.
> - Inside the window no conflict halts. Authority (§5.4) and static-value (§5.7) conflicts are recorded and each sample is disposed of as `FirstWriterWins` would; the close reads `Authority::conflicts()` and `StaticStore`.
> - At the close, under `Strict` only, a non-empty record halts once with `StartupConflicts { authority, statics }`, and `detail` enumerates every recorded edge with both publishers.
> - Outside the window `Strict` degrades to `FirstWriterWins` plus counters.
> - A window-close halt charges no counter bucket, or §5.9's ledger would not balance.

The diagnostic must be loud, rate-limited, and surfaced in `tf_tree doctor`, because **this is the feature that finds pre-existing bugs in the host system** (§1, criterion 3). `tf2` interleaves competing publishers by timestamp into a silent blend; "your `/ekf` and `/odom_node` have both been publishing `odom→base_link` for eight months" is a better sales pitch than any latency number.

> **Clarification — rate-limiting applies to the stop as well.** `tft_bridge_outcome::first_time` is the whole rate limiter. The arm that stops the bridge sets `first_time = 1` (it runs once per bridge) and the latched replay path leaves it 0, so every arm of the `rclcpp` `report()` gates on the same field.

### 5.5 Time domains and simulation

If `use_sim_time` is true, the bridge tags every edge it declares as `SimDomain` and drives its clock from `/clock`; otherwise `SystemDomain`. A consumer querying with the wrong domain gets `TimeDomainMismatch` instead of a plausible wrong answer.

> **Amendment — domain names and the derivation gap.** Domains are `SystemDomain` 0, `SensorDomain` 1, `SimDomain` 2, `SteadyDomain` 3 ([`API.md`](./API.md) §2.5). `tf_tree_bridge::config::parse_domain` maps `"system"`, `"sensor"`, `"sim"`, `"steady"` through `Domain::TAG`; every other end (`EdgeRecord::domain`, `tft_bridge_options::domain`, the node's `time_domain` parameter, `tf_tree topology --domain N`) carries the integer. `TopologyConfig::default_domain` stays a `u8` because `Domain` is an open trait (user domains use tags from 4).
>
> **Remainder:** nothing derives the bridge's tag from `use_sim_time`. The tag is the explicit `time_domain` parameter (default `0`, in `ros/tf_tree_ros/src/bridge_node.cpp`); the node warns when `use_sim_time` is true and `time_domain` is 0. Consequences:
>
> - `use_sim_time` true, `time_domain` and the config domain both `0`: the bridge comes up tagged `SystemDomain`; the warning and the `domain=%u` in the `ingest bridge up` INFO line are the only signals.
> - `use_sim_time` true, config `domain = "sim"`, `time_domain` left `0`: **the bridge does not come up** — `check_domain` sees a dynamic edge declared 2 against tag 0, `tft_bridge_create` returns `TFT_ERR_TIME_DOMAIN`, and `BridgeHandle` throws `BridgeError`.
>
> Closing the gap means making the tag follow `use_sim_time` in `bridge_node.cpp` (gated by `just ros-test`). **This is the one place the remainder is recorded**; [`API.md`](./API.md) §2.5 and [`PHASE7.md`](./PHASE7.md) §4 J9 point here.

**NORMATIVE:** the bridge refuses to write to an edge whose declared domain differs from its own, and fails at startup rather than at first message. `TopologyConfig::check_domain` refuses any *dynamic* edge with a different domain, called from `tft_bridge_create` before the arena is built and from `tf_tree topology --config <f> --domain N`. Static edges are exempt (`robot_state_publisher` stamps `/tf_static` at zero).

> This is the write side only. The query side is specified by [`PHASE7.md`](./PHASE7.md) §4 J9; until then a native consumer names its domain in the type (D9) and nothing infers it from `use_sim_time`. [`API.md`](./API.md) §5.2 records why an epoch mistake is unfixable after the fact.

Also handle `/clock` jumping backwards (bag loop, sim reset): the bridge **stops and reports** rather than pushing non-monotonic stamps. `--on-clock-reset={halt,recreate}`.

> **Amendment — the sentence above is superseded.** A jump is reported first via `Ingest::note_time_jump` / `tft_bridge_note_time_jump`; a single source is dropped and never halts; forward jumps are covered. `0011` is superseded — do not cite its Decision 1. See [`0012`](./decisions/0012-the-authoritative-clock-jump-signal-and-the-degradation-ladder.md): §*Context* (*The three rules, and what killed each*), §*Decision* (*The five principles*, *L1 — the authoritative path*, *L2 — inference as common-mode rejection*, *L3 — the degradation ladder*) and §*Known limitations*.

### 5.6 Frame names

Strip a single leading `/` (ROS 1 legacy) and warn once per distinct frame. Reject empty names. Otherwise pass UTF-8 through unchanged — frame names are identifiers, and two frames differing only by case are two frames.

Apply `tf_prefix` remapping if configured, and log the resulting mapping table at startup. A silent remap is worse than no remap.

> **Clarification — `tf_prefix` applies to the topology config as well as the wire, and the arena is built from the result.** §5.8's config is the sole source of declared edges, so remapping only the wire made every transform `UndeclaredEdge`. The config's declared frames go through the same `NameNormalizer` (via `TopologyConfig::rewritten`), so `--discover` output needs no hand-editing per robot and there is one normalized topology in the process. The remap table is complete at startup, exposed to C as `tft_bridge_get_remap`.

### 5.7 Static transform semantics

`/tf_static` messages arriving for an edge already declared static:

- **Identical value** (bitwise, or within 1e-12): idempotent, ignore silently (late joiners re-receive latched messages).
- **Different value**: diagnostic naming both publishers and both values, **then** apply the authority policy.

A transform arriving on `/tf_static` for an edge declared *dynamic* (or vice versa) is a hard error: the edge kind cannot change.

> **Amendment — the engine has no runtime edge declaration.** `Tree` has no post-build `declare_*` (`TreeBuilder::{static_edge, dynamic_edge}` are consuming, `Tree::claim` returns `NoEdge` for an undeclared child; decision `0004`, D4). A bridge therefore cannot learn topology from `/tf`, and a static edge's pose is inline in `EdgeRecord::static_pose` with capacity 0.
>
> **The bridge takes its topology up front** from a config file (`tf_tree serve --config <topology.toml>` per [`0019`](./decisions/0019-one-binary-and-topology-you-can-wait-for.md)); a transform for an undeclared edge is dropped, counted and diagnosed once per edge naming both frames (`Action::UndeclaredEdge`, `BridgeStats::dropped_undeclared`). `Action::StaticVerified` means *verify against the declared constant*. `tf_tree topology --discover` collects and prints a config file. A runtime `declare_edge` would need a decision record and would fight D4.
>
> **An empty topology is refused in `tft_bridge_create`**, so all three §5.8 forms inherit it; `BridgeNode`'s both-or-neither parameter check stays because it tells the operator which parameter to set.

### 5.8 Deployment forms

Three, in increasing order of integration:

1. **Standalone node** `tf_tree_bridge`. Zero code changes to the host system.
2. **`rclcpp` component.** Composable into an existing container; intra-process communication avoids serialization.
3. **In-process library handle.** `tf_tree::ros::BridgeHandle handle(node, opts);` attached to an existing node. Lowest friction, and for dogfooding, us.

All three share one implementation; only the lifecycle wrapper differs.

> **Amendment — a dedicated callback group is design, not a wrapper.** `tft_bridge` is `Send + !Sync` and the affinity is checked: the thread calling `tft_bridge_create` is the only one that may offer, read stats, or free. Subscriptions therefore use `SubscriptionOptions::callback_group` set to a group created with `create_callback_group(MutuallyExclusive, /*automatically_add_to_executor_with_node=*/false)`, taken by the bridge's own executor via `add_callback_group`. Left at the default, a caller who spins the node gets `TFT_ERR_WRONG_THREAD` on every transform.
>
> - `stats()` cannot be a live read; the ingest thread refreshes a mutex-protected snapshot after each `TFMessage`.
> - §5.3's refresh cannot be a graph-event handler; `ros/tf_tree_ros` walks the graph from the ingest thread on the first message from an unseen GID.
> - `test_executor.cpp` (its own ctest binary) gates the flag: it attaches the bridge to a node the caller's executor already spins, where the mutant throws on the ingest thread and `std::terminate`s.

> **Amendment ([`0015`](./decisions/0015-the-bridge-fills-a-shared-arena.md)) — where the arena lives is a second axis all three forms choose on.** `tft_bridge_options::arena_name`: non-NULL publishes the arena under that rendezvous name, attachable **read-only** via `tft_tree_open()` (C), `tf_tree::open()` (Rust) or `tf_tree.open()` (Python), with no new consumer API. NULL (default) keeps the private heap arena. This is not a fourth form.
>
> - Forms 1 and 2 (`BridgeNode`) take it from the `arena_name` ROS parameter (default `""`); form 3 has no parameters, so `BridgeOptions::arena_name` (empty = private) is its whole surface. `test_shared_arena.cpp` asserts the two paths separately.
> - At the parameter layer an `arena_name` that is all whitespace or has whitespace at either end is **refused, not trimmed**; every other malformed name is `tf_tree_ipc::ArenaName`'s to refuse. `BridgeHandle` maps `""` to NULL.
> - **A bridge asked for a shared arena it cannot have refuses to start** (`TFT_ERR_ARENA_UNAVAILABLE`, ABI minor 4 → 5), with **no fallback to a heap arena**, including in a `bridge`-without-`shm` build.

### 5.9 Executor and backpressure

Dedicated `SingleThreadedExecutor` on its own thread, with optional CPU affinity and `SCHED_FIFO` priority (off by default; document the `ulimit`/capability requirements).

Track and expose: messages received, transforms applied, dropped by authority, dropped by non-monotonic stamp, and subscription queue depth.

> **Amendment — "subscription queue depth" is not an API that exists.** No `rclcpp`/`rcl`/`rmw` call reports how many messages wait in a subscription. The middleware reports `SubscriptionEventCallbacks::message_lost_callback` (`rmw_message_lost_status_t`), which answers "is the bridge the bottleneck?" directly. `tft_bridge_stats` keeps `queue_high_water` and `tft_bridge_note_queue_depth` for replay harnesses; `ros/tf_tree_ros` does not call it, so the field reads 0.
>
> Open: `queue_capacity` is hard-coded to 100 in `tf_tree_bridge` with no ABI setter (needs a `struct_size` bump). CPU affinity and `SCHED_FIFO` are **not implemented**.

> **Amendment — the test as first specified cannot pass.** DDS `TRANSIENT_LOCAL` durability is scoped to the **writer's** lifetime (measured on `rmw_fastrtps_cpp`; the participant's departure is neither necessary nor sufficient):
>
> | publisher | subscriber | result |
> |---|---|---|
> | exited after publishing | `transient_local` | **nothing** |
> | exited after publishing | `volatile` | nothing |
> | alive, silent | `transient_local` | **received** |
> | alive, silent | `volatile` | **nothing** |
>
> So the test is: **a static broadcaster publishes once, stays alive, and never publishes again; the bridge starts afterwards and must receive the transform, and a `volatile` subscriber in the same run must not.** The `volatile` negative control is the half that catches the regression. A `robot_state_publisher` that has exited takes its latched transforms with it; no subscriber QoS recovers them.
>
> This covers only the durability half of §5.2. The third test in `test_qos.cpp` asserts every field of both rows against `get_actual_qos()`; the durability mutant dies in both styles, the reliability and depth mutants only in the second.
