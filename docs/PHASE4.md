### Findings the design must keep

- **Layout read direction.** A publisher needs four layouts as *inputs* (matrix→quaternion by Shepperd's method, plus a determinant check: `det R = −1` is a reflection, `det R = s³` a scaled `Affine3d`). `AFFINE12_ROW_F32` is write-only.
- **Id spaces.** `EdgeId` and `FrameId` report `1 ..= count` across the C ABI; `tft_tree_instance_uuid` returns `TFT_ERR_NO_DATA` for a private arena.
- **Bridge ordering.** Names normalized before anything keys on them; static-value check before authority; authority before the clock; a static's stamp never touches the clock. The reset threshold is 100 ms by default. `recreate` stops the bridge exactly like `halt`.
- **`TFT_BRIDGE_REJECTED` is unreachable from a heap-arena bridge**; the arm stays so a broken invariant does not present as "applied, but no data". The outcome POD is written twice per offer on purpose: the blank write must precede handle validation (`a_bad_handle_still_leaves_a_printable_outcome`).
- **Attribution refresh is on the ingest thread, before offering**, triggered by an unseen GID and capped at 20 walks per unmatched GID. A periodic refresh is wrong: under `FirstWriterWins` the first sample fixes the owner's name.
- **Static-archive build.** `ros/build.sh` links the static target, makes one `nm` symbol check per default-off feature (`bridge`, `shm`), and deletes `*/test_results` before `colcon test`; `TFT_HAVE_SHM` is probed per target by `crates/tf_tree_c/CMakeLists.txt`.
- **`is_trivially_copyable` is the wrong gate for a raw layout write** (`Eigen::Transform` declares a copy constructor); the wrapper uses `tf_tree::raw_writable<T>` plus a run-time premise check.
- `examples/bridge_cost.rs` is **not** gate criterion 3. `tests/steady_state_alloc.rs` in `tf_tree_bridge` budgets 2 allocations per accepted or undeclared offer and 0 per refused one.

### What this environment cannot gate

- One RMW (§5.3's degrade-gracefully path is untested), no clang in the ROS image; §6.3's bag-replay and byte-identical-arena rows need a bag through `rosbag2_cpp`.
- §5.9's CPU affinity and `SCHED_FIFO` are not implemented; `message_lost_callback` and `incompatible_qos_callback` fire in no test.
- No robot and no two-week window: §1's criteria gate Phase 7 and stay open. The benchmark host is not a fair comparison machine; §7 gate criterion 3 prints `UNAVAILABLE` with a reason.

## 1. What Phase 4 must prove

Feature completion is not the gate. The gate is:

1. **A real node, on real hardware, for ≥ 2 weeks continuous**, consuming transforms from `tf_tree` via the bridge, with no correctness incident.
2. **A written log of every surprise** — API friction, missing operations, confusing errors, deployment papercuts; the design input for Phase 7. **Every entry is filed against a [`PHASE7.md`](./PHASE7.md) §4 J-row or opens a new one**; that is the only Phase 7 work authorized before its §0.0 gates are met. Entries about *our* design rather than `tf2`'s behaviour get their own decision record ([`0017`](./decisions/0017-owned-handles-and-the-lifetime-rule.md), [`0018`](./decisions/0018-blocking-waits-belong-in-the-shim.md)).
3. **At least one pre-existing bug found in the host system** by the bridge's multi-publisher detection (§5.4): a falsifiable prediction, since `tf2` averages competing publishers silently. If two weeks finds nothing, either the detection is broken or the host stack is unusually clean — determine which.

Do not proceed to Phase 5 having only met criterion 1.

## 2. `sample_with_derivatives` — pulled forward

### 2.1 Why now

It is the clearest signal that `tf_tree` is a different primitive rather than a faster `tf2`, and it adds no transcendental call under ScLerp.

### 2.2 API

`Twist { omega: Vec3, v: Vec3 }` (rad/s, m/s); `Sample { pose: Iso3, twist: Twist, accel: Option<Twist> }` (`accel` is `None` for ScLerp/LerpSlerp, `Some` for splines in Phase 6); `Plan::at_with_derivatives(&self, g: &Guard, t: Stamp) -> Result<Sample, LookupError>`.

**Convention — NORMATIVE:** twists are **body-frame (right) twists**, `V^b = (T⁻¹ Ṫ)^∨`, matching the right-perturbation convention of Phase 1 §3.1. `Twist::to_spatial(&self, t: &Iso3)` = `Ad(T) V^b`.

### 2.3 ScLerp gives an exact, constant body twist

For `T(s) = a · exp(s · ξ^)` with `ξ = log(a⁻¹b)` and `s = (t − t₀)/Δt`:

```
V^b(t) = ξ / Δt        — constant across the whole segment
```

`ScLerp::eval` works in unit-dual-quaternion screw form and does not compute `ξ`; it is recoverable from the intermediates without an additional transcendental, via a `screw_pow` variant returning them alongside the pose.

Composition along a plan (add both as proptests): `T_ac = T_ab · T_bc ⇒ V_ac^c = Ad(T_bc⁻¹) · V_ab^b + V_bc^c`, and `S = T⁻¹ ⇒ V_S^b = −Ad(T) · V_T^b`. For `T = (q, t)`, `Ad(T⁻¹)·[ω; v] = [q*·ω; q*·(v − t × ω)]` and `Ad(T)·[ω; v] = [q·ω; t × (q·ω) + q·v]`; no 6×6 is built.

### 2.4 LerpSlerp and ScLerp differ in the linear part

LerpSlerp and ScLerp produce the same angular velocity, but LerpSlerp's world-frame velocity is constant, so its body-frame velocity rotates through the segment (a spurious lateral acceleration; `|v|` stays constant, so **a magnitude check will not catch it**). This is a reason ScLerp is the default.

**NORMATIVE:** `at_with_derivatives` returns `Err(DerivativesUnavailable { edge, interp })` for `LerpSlerp` edges rather than a misleading value.

## 3. The C ABI

### 3.1 Two tiers — NORMATIVE

| Header | Contents | Guarantee |
|---|---|---|
| `tf_tree.h` | open/close, plan, at, at_many, publisher, declare, errors, version | **semver, frozen at 1.0** |
| `tf_tree_unstable.h` | everything else — introspection, diagnostic counters, adaptive, derivatives | none; requires `#define TFT_ENABLE_UNSTABLE` |

**Do not mirror the Rust API into C.** Anything a C++ user does not need in the hot path belongs in the unstable header.

### 3.2 Handles and ownership

`tft_tree` and `tft_plan` are `Send + Sync` (shareable; a plan is immutable); `tft_publisher` is `Send + !Sync` — **one thread at a time**.

Every `tft_*_create`/`_open` pairs with exactly one `tft_*_free`. Freeing NULL is a no-op; double-free is undefined and detected in debug builds.

**`tft_publisher` thread affinity — NORMATIVE.** Record the creating thread id in the handle and, in debug builds, `abort()` with a clear message on use from another thread. `tft_bridge` has the same affinity; freeing it from the wrong thread is refused and leaks the handle (`TFT_ERR_WRONG_THREAD` in release, `SIGABRT` naming `tft_bridge` in debug).

### 3.3 Error model

Status code (`tft_status`, `int32_t`; 0 = ok, negative = error) plus a thread-local structured `tft_error`: `struct_size`, `code`, `edge` (`TFT_INVALID_ID` when N/A), `frame_a`, `frame_b`, `requested`/`oldest`/`newest`, `plan_generation`/`current_generation`, and a NUL-terminated `message[256]` with names resolved. `tft_last_error()` is never NULL and is valid until the next tf_tree call **on the same thread**. Message formatting happens only on the error path.

### 3.4 Panic safety — NORMATIVE

**Every `extern "C"` entry point wraps its body in `std::panic::catch_unwind`**, converting a panic into `TFT_ERR_INTERNAL` with the payload copied into `message`. A benchmark row proves the happy-path cost (§7).

### 3.5 Layouts — and the quaternion order trap

Layouts: `TFT_LAYOUT_QVEC7_WXYZ` (0, `[qw qx qy qz tx ty tz]` f64, canonical, matches the arena), `QVEC7_XYZW` (1, Eigen/Sophus coefficient order), `MAT4_COL` (2, f64 column-major, Eigen), `MAT4_ROW` (3, f64 row-major, C/NumPy), `AFFINE12_ROW_F32` (4, 3x4 f32 row-major, GPU).

Two traps, both producing plausible wrong answers:

- **Quaternion component order.** Canonical is `w`-first; `Eigen::Quaterniond` stores `(x, y, z, w)`, so a `memcpy` from `QVEC7_WXYZ` into it or into `Sophus::SE3d` is silently wrong. Use `QVEC7_XYZW`.
- **Matrix major order.** Row- and column-major differ by a transpose, which for a rotation is its inverse. The enum is explicit and there is no default.

**NORMATIVE test:** for every layout, round-trip a known transform through the C ABI and assert against a hand-computed expected byte pattern, not against another tf_tree call.

### 3.6 ABI versioning

`tft_abi_version_major()` / `tft_abi_version_minor()`. **Major must match exactly**; the runtime minor may be ≥ the compiled-against minor. Every struct passed by pointer begins with `uint32_t struct_size`, so fields can be appended without a major bump; the callee validates `struct_size` and rejects unknown sizes.

**Appending a `tft_layout` enumerator is a minor bump**: an older caller never names it, and `tft_plan_at` rejects an unknown enumerator (`bad_enum("layout")`). This is the path [`API.md`](./API.md) §3.3 uses to carry `Layout::QuatTwist` into C and Python in Phase 5.

The C++ header checks the version in a static initializer and throws / aborts on mismatch.

### 3.7 The hot path

`tft_plan_at(plan, stamp, layout, out)` and `tft_plan_at_many(plan, stamps, n, layout, out, out_stride_bytes)`. `out_stride_bytes` writes directly into an array of user structs whose element size exceeds the payload (§4.3). Zero means tightly packed. No allocation, no locking. Gate: §7 criterion 1.

## 4. The C++ wrapper

### 4.1 Shape

Header-only, C++17, `namespace tf_tree`. RAII handles with deleted copy and defaulted move; every function is a thin inline over the C ABI, no logic. Error modes are selected at include time: by default calls throw `tf_tree::Error` carrying the full `tft_error`; under `#define TF_TREE_NO_EXCEPTIONS` every call returns `tf_tree::expected<T, Error>` (`std::expected` when C++23 is available).

### 4.2 Eigen interop

`Eigen::Isometry3d` is a 128-byte column-major `Matrix4d`, so **an array of them is tightly packed and `TFT_LAYOUT_MAT4_COL` writes into it with no copy and no stride** (`plan.at<Eigen::Isometry3d>(stamp)`, `plan.at_many(stamps, out)`), asserted by `static_assert(sizeof(Eigen::Isometry3d) == 128)`. C++17's over-aligned `new` makes `std::vector<Eigen::Isometry3d>` correct without `Eigen::aligned_allocator`; the convenience overload carries `static_assert(__cplusplus >= 201703L)`.

### 4.3 Sophus interop and the alignment hazard

`Sophus::SE3d` is a 56-byte payload whose `sizeof` commonly rounds to 64, so **an array of `SE3d` is usually not tightly packed** and a `memcpy` of `n × 56` bytes corrupts every element after the first. Pass `out_stride_bytes = sizeof(Sophus::SE3d)` with `TFT_LAYOUT_QVEC7_XYZW`. `sizeof` is read at compile time, never assumed; the wrapper checks the quaternion precedes the translation with no interior padding before enabling the direct path, else falls back to an element-wise loop.

### 4.4 Packaging

`find_package(tf_tree CONFIG)` exports `tf_tree::tf_tree` (shared) and `tf_tree::tf_tree_static` with `INTERFACE_COMPILE_FEATURES cxx_std_17`. Source builds go via **`corrosion`**, so `colcon build` works without hand-managed cargo; prebuilt static libraries for `x86_64` and `aarch64` `linux-gnu` are preferred when the target matches. A ROS binary package (bloom/rosdep) is Phase 7.

## 5. The ROS 2 ingest bridge

### 5.1 Ingress only — NORMATIVE

The bridge subscribes `/tf` and `/tf_static` and writes into the arena. It does **not** publish.

### 5.2 QoS — get this wrong and you silently receive nothing

**NORMATIVE**, matching `tf2_ros::TransformListener`: `/tf` is `KeepLast(100)`, **reliable**, **volatile**; `/tf_static` is `KeepLast(100)`, **reliable**, **transient_local**.

A `volatile` subscription to `/tf_static` receives nothing from publishers that started earlier and never publish again: the most common ROS 2 tf integration bug, with no error anywhere. The startup line reports the *negotiated* QoS (`Subscription::get_actual_qos()` read back at construction), and `incompatible_qos_callback` is installed on both subscriptions; `test_qos.cpp` asserts both fields and the depth against `get_actual_qos()`.

### 5.3 Publisher attribution — the bridge is a bug detector

`TFMessage` carries no publisher identity, but the middleware does: `rmw_message_info_t::publisher_gid` matches `TopicEndpointInfo::endpoint_gid()` from `Node::get_publishers_info_by_topic("/tf")`, which also gives `node_name()` and `node_namespace()`. Cache the match, refreshed before offering a message whose GID is unseen (§5.8's threading rule forbids a graph-event handler).

**Degrade gracefully:** GID reporting varies across RMW implementations; on failure keep running with the publisher unattributed. **The identity is the GID; the name is presentation** (`rmw_fastrtps` reports `_NODE_NAME_UNKNOWN_` until node information arrives):

- `Publisher::Gid` carries the rendered GID as identity and the node name as `Option<String>`; `PartialEq`, `Ord` and `Hash` read the identity alone and are hand-written so a new field cannot rejoin the key.
- `tft_bridge_attribute` updates a name, never an identity. A GID with no name is a distinct publisher and prints its GID.
- `Publisher::Unattributed` (no GID at all) stays a unit variant: less attribution means less detection, never more stopping. Offline ingest uses `Publisher::Topic`.

**No decision that can stop, restart or refuse the bridge may be a function of publisher identity or of the number of distinct publishers** ([`0012`](./decisions/0012-the-authoritative-clock-jump-signal-and-the-degradation-ladder.md)). Identity may change what is reported, never what is done; a detector degrades in sensitivity, never toward action. §5.5's ladder satisfies both: a single witness never halts, at any magnitude.

### 5.4 Authority policy — NORMATIVE

ROS permits any number of publishers per edge; `tf_tree` permits exactly one (D7).

| Policy | Behaviour |
|---|---|
| `FirstWriterWins` (**default**) | The first attributed publisher of an edge owns it. Later publishers' samples are dropped and counted, with a diagnostic naming **both** nodes and the edge. |
| `LastWriterWins` | Reclaim on each new publisher. Documented as chaotic, never the default. |
| `Strict` | Refuse to start if a conflict is detected within a startup window. For CI. |

**`Strict` halts once at the close of the startup window, not on the message that conflicts** ([`0011`](./decisions/0011-the-bridge-clock-guard-and-the-static-conflict-disposition.md)):

- The window is open from construction and closes at the first of: an explicit `close_startup_window()` (the `rclcpp` node drives it from a one-shot **steady** timer, `startup_window_sec` default 5.0, never `node_->get_clock()`); or a backstop of 4096 transforms.
- Inside the window no conflict halts: authority (§5.4) and static-value (§5.7) conflicts are recorded and each sample is disposed of as `FirstWriterWins` would. At the close, under `Strict` only, a non-empty record halts once with `StartupConflicts { authority, statics }`, and `detail` enumerates every recorded edge with both publishers. Outside the window `Strict` degrades to `FirstWriterWins` plus counters.
- A window-close halt charges no counter bucket, or §5.9's ledger would not balance.

The diagnostic must be loud, rate-limited, and surfaced in `tf_tree doctor`, because **this is the feature that finds pre-existing bugs in the host system** (§1, criterion 3). `tft_bridge_outcome::first_time` is the whole rate limiter: the arm that stops the bridge sets `first_time = 1` and the latched replay path leaves it 0, so every arm of the `rclcpp` `report()` gates on the same field.

### 5.5 Time domains and simulation

If `use_sim_time` is true, the bridge tags every edge it declares as `SimDomain` and drives its clock from `/clock`; otherwise `SystemDomain`. A consumer querying with the wrong domain gets `TimeDomainMismatch` instead of a plausible wrong answer.

Domains are `SystemDomain` 0, `SensorDomain` 1, `SimDomain` 2, `SteadyDomain` 3 ([`API.md`](./API.md) §2.5). `tf_tree_bridge::config::parse_domain` maps `"system"`, `"sensor"`, `"sim"`, `"steady"` through `Domain::TAG`; every other end (`EdgeRecord::domain`, `tft_bridge_options::domain`, the node's `time_domain` parameter, `tf_tree topology --domain N`) carries the integer. User domains use tags from 4.

**Remainder:** nothing derives the bridge's tag from `use_sim_time`. The tag is the explicit `time_domain` parameter (default `0`, in `ros/tf_tree_ros/src/bridge_node.cpp`); the node warns when `use_sim_time` is true and `time_domain` is 0. With both `0` the bridge comes up tagged `SystemDomain` and the warning is the only signal; with config `domain = "sim"` and `time_domain` left `0`, **the bridge does not come up**: `check_domain` sees a dynamic edge declared 2 against tag 0, `tft_bridge_create` returns `TFT_ERR_TIME_DOMAIN`, and `BridgeHandle` throws `BridgeError`. Closing the gap means making the tag follow `use_sim_time` in `bridge_node.cpp` (gated by `just ros-test`). **This is the one place the remainder is recorded**; [`API.md`](./API.md) §2.5 and [`PHASE7.md`](./PHASE7.md) §4 J9 point here.

**NORMATIVE:** the bridge refuses to write to an edge whose declared domain differs from its own, and fails at startup rather than at first message. `TopologyConfig::check_domain` refuses any *dynamic* edge with a different domain, called from `tft_bridge_create` before the arena is built and from `tf_tree topology --config <f> --domain N`. Static edges are exempt (`robot_state_publisher` stamps `/tf_static` at zero).

This is the write side only; the query side is [`PHASE7.md`](./PHASE7.md) §4 J9. Until then a native consumer names its domain in the type (D9) and nothing infers it from `use_sim_time`.

`/clock` jumping backwards (bag loop, sim reset) is reported first via `Ingest::note_time_jump` / `tft_bridge_note_time_jump`; a single source is dropped and never halts; forward jumps are covered. `--on-clock-reset={halt,recreate}`. See [`0012`](./decisions/0012-the-authoritative-clock-jump-signal-and-the-degradation-ladder.md) §*Decision* (*L1*–*L3*); `0011`'s Decision 1 is superseded.

### 5.6 Frame names

Strip a single leading `/` (ROS 1 legacy) and warn once per distinct frame. Reject empty names. Otherwise pass UTF-8 through unchanged. Apply `tf_prefix` remapping if configured, and log the resulting mapping table at startup. It applies to the topology config as well as the wire: the config's declared frames go through the same `NameNormalizer` (via `TopologyConfig::rewritten`), so there is one normalized topology in the process and `--discover` output needs no per-robot editing. The remap table is complete at startup, exposed to C as `tft_bridge_get_remap`.

### 5.7 Static transform semantics

`/tf_static` messages arriving for an edge already declared static:

- **Identical value** (bitwise, or within 1e-12): idempotent, ignore silently (late joiners re-receive latched messages).
- **Different value**: diagnostic naming both publishers and both values, **then** apply the authority policy.
- A transform on `/tf_static` for an edge declared *dynamic* (or vice versa) is a hard error: the edge kind cannot change.

**The engine has no runtime edge declaration.** `Tree` has no post-build `declare_*` (`TreeBuilder::{static_edge, dynamic_edge}` are consuming, `Tree::claim` returns `NoEdge` for an undeclared child; decision `0004`, D4), so the bridge takes its topology up front from a config file (`tf_tree serve --config <topology.toml>` per [`0019`](./decisions/0019-one-binary-and-topology-you-can-wait-for.md)). A transform for an undeclared edge is dropped, counted and diagnosed once per edge naming both frames (`Action::UndeclaredEdge`, `BridgeStats::dropped_undeclared`); `Action::StaticVerified` means *verify against the declared constant*. `tf_tree topology --discover` collects and prints a config file. A runtime `declare_edge` would need a decision record.

**An empty topology is refused in `tft_bridge_create`**, so all three §5.8 forms inherit it; `BridgeNode`'s both-or-neither parameter check stays because it tells the operator which parameter to set.

### 5.8 Deployment forms

Three, in increasing order of integration:

1. **Standalone node** `tf_tree_bridge`. Zero code changes to the host system.
2. **`rclcpp` component.** Composable into an existing container; intra-process communication avoids serialization.
3. **In-process library handle.** `tf_tree::ros::BridgeHandle handle(node, opts);` attached to an existing node.

All three share one implementation; only the lifecycle wrapper differs.

**A dedicated callback group is design, not a wrapper.** `tft_bridge` is `Send + !Sync` and the affinity is checked: the thread calling `tft_bridge_create` is the only one that may offer, read stats, or free. Subscriptions therefore use `SubscriptionOptions::callback_group` set to a group created with `create_callback_group(MutuallyExclusive, /*automatically_add_to_executor_with_node=*/false)`, taken by the bridge's own executor via `add_callback_group`; left at the default, a caller who spins the node gets `TFT_ERR_WRONG_THREAD` on every transform. `stats()` is a mutex-protected snapshot the ingest thread refreshes after each `TFMessage`. `test_executor.cpp` gates the flag.

**Where the arena lives is a second axis all three forms choose on** ([`0015`](./decisions/0015-the-bridge-fills-a-shared-arena.md)). `tft_bridge_options::arena_name`: non-NULL publishes the arena under that rendezvous name, attachable **read-only** via `tft_tree_open()` (C), `tf_tree::open()` (Rust) or `tf_tree.open()` (Python); NULL (default) keeps the private heap arena.

- Forms 1 and 2 (`BridgeNode`) take it from the `arena_name` ROS parameter (default `""`); form 3 uses `BridgeOptions::arena_name` (empty = private). `test_shared_arena.cpp` asserts the two paths separately.
- An `arena_name` that is all whitespace or has whitespace at either end is **refused, not trimmed**; every other malformed name is `tf_tree_ipc::ArenaName`'s to refuse. `BridgeHandle` maps `""` to NULL.
- **A bridge asked for a shared arena it cannot have refuses to start** (`TFT_ERR_ARENA_UNAVAILABLE`, ABI minor 4 → 5), with **no fallback to a heap arena**, including in a `bridge`-without-`shm` build.

### 5.9 Executor and backpressure

Dedicated `SingleThreadedExecutor` on its own thread, with optional CPU affinity and `SCHED_FIFO` priority (off by default; document the `ulimit`/capability requirements).

Track and expose: messages received, transforms applied, dropped by authority, dropped by non-monotonic stamp, and subscription queue depth. No `rclcpp`/`rcl`/`rmw` call reports how many messages wait in a subscription; the middleware reports `message_lost_callback`, which answers "is the bridge the bottleneck?" directly. `tft_bridge_stats` keeps `queue_high_water` and `tft_bridge_note_queue_depth` for replay harnesses; `ros/tf_tree_ros` does not call it, so the field reads 0.

Open: `queue_capacity` is hard-coded to 100 in `tf_tree_bridge` with no ABI setter (needs a `struct_size` bump). CPU affinity and `SCHED_FIFO` are **not implemented**.

## 6. Test plan

### 6.1 C ABI

- Every function called with NULL handles, NULL out-pointers, zero-length arrays and mismatched `struct_size` → correct status, no crash, no UB under ASan/UBSan.
- Double-free, use-after-free, and `tft_publisher` used from a second thread → debug-build abort with a named message.
- A forced panic in Rust (test-only hook) → `TFT_ERR_INTERNAL`, process survives, `tft_last_error()` carries the payload.
- ABI major/minor mismatch → rejected at init with both versions named; byte-pattern assertions for all layouts (§3.5).

### 6.2 C++ wrapper

- Compiles clean under `-Wall -Wextra -Wpedantic`, with and without `-fno-exceptions`, C++17 and C++20, GCC and Clang; ASan/UBSan across the whole suite.
- `static_assert` suite for Eigen and Sophus layouts; the Sophus stride fallback exercised by forcing the assert off.
- Eigen batch write touches exactly `n * sizeof(Isometry3d)` bytes (guard pages either side).

### 6.3 Bridge

- **QoS regression test** (`ros/tf_tree_ros/test/test_qos.cpp`): DDS `TRANSIENT_LOCAL` durability is scoped to the **writer's** lifetime, so a static broadcaster **publishes once, stays alive, and never publishes again; the bridge starts afterwards and must receive the transform, and a `volatile` subscriber in the same run must not.** The `volatile` negative control is the half that catches the regression. A publisher that has exited takes its latched transforms with it; no subscriber QoS recovers them. This covers only the durability half of §5.2; the third test asserts every field of both rows against `get_actual_qos()`.
- Two publishers on one edge → `FirstWriterWins` applied, diagnostic names both nodes, counter increments.
- Sim time: `/clock` driven, domains tagged, cross-domain query rejected. Clock reset backwards → halt or recreate per policy, never non-monotonic pushes.
- Static conflict with differing values → diagnostic; identical values → silent. Frame name with leading `/` → stripped, warned once.
- Bag replay at 10× real time → no drops, queue depth bounded; all three deployment forms produce byte-identical arena contents from the same bag.

### 6.4 End-to-end

Replay a recorded bag through the bridge and compare `tf_tree` lookups against `tf2` lookups over the same query set using `LerpSlerp`, asserting agreement to 1e-12 (the Phase 1 differential test through the real ROS path). Any disagreement is a bridge bug.

## 7. Benchmarks and the gate

The native *embedding* path is [`API.md`](./API.md) §2.3's **NORMATIVE** row (facade from a separate crate against the in-crate path, gated at 5%), landing in the Phase 5 artifact (`PHASE5.md` §9.2).

**Gate:**

1. **C ABI, measured at `[profile.embedder]` (`lto = false`) by `just abi-cost`, on an interleaved five-arm ladder** — the four quotients R1, R2, R3 and control C of §0.0's table, each differing from its comparand by one thing: R3 (*primary*) prices the per-call `Guard`; R1 handle validation, layout dispatch and the output slice; R2 `catch_unwind`; C is the instrument, and if it disagrees the run is red before any rung is believed. R3 is primary because [`0022`](./decisions/0022-the-per-call-guard-and-the-unwatched-gate.md) prices the per-call guard at ~85% of what a C++ caller pays over native Rust. **R3's allowance on the §11.1 fixture is not yet set**, so it is reported, not gated; the recipe still gates the three-edge R3 at 1.25 and prints that distinction beside the number. **R1's 1.10 is provisional**; `0023`'s implementation step 5 re-derives it.
2. C++ wrapper within **2%** of the C ABI (it is inline code; anything more means it is not).
3. Bridge steady-state CPU **below one `tf2` consumer's** — the architectural claim is that this cost is paid once instead of N times.
4. Zero ASan/UBSan findings across the C and C++ suites.
5. §6.4 differential test passes to 1e-12.
6. §1's operational criteria met, including the surprise log.
